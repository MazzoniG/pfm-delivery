Rules for this screen

  1. The URL is the state. Selected account, date range and search live in search params, and the query key derives from them. Nothing here goes in Zustand.
  2. The sidebar lists asset and liability accounts only, grouped by kind. No balances yet: leave the header slot empty rather than stubbing a number. Archived accounts are hidden.
  3. Month rows are presentation only, grouped client-side from occurredOn. Days are shown without the month because the group carries it.
  4. Category shows the counter-side of the entry. One counter line shows its name; a transfer shows the other account; more than one shows Split, which opens the split detail.
  5. Amounts render exactly as the API returns them, through the shared money formatter. No arithmetic, no sign flipping, no Math.abs, no parseFloat.
  6. A lock marks a reconciled row. A correction appears as a reversal plus a replacement dated the day it was made; each badge links to the other and to the original.
  7. Pagination is keyset. The button passes the cursor from the last response. No page numbers, no totals.
  8. No user avatar, switcher or owner selector anywhere. Identity belongs to the server.

Rules for this dialog

  1. Money out and Money in submit the simple form (account, category, amount). Transfer submits two lines between two accounts, from and to. There is no transfer endpoint; it is an ordinary entry.
  2. The account picker shows asset and liability accounts only, grouped by kind. The category picker shows expense categories on Money out and income categories on Money in. An income or expense row never appears in an account picker.
  3. React Hook Form with zodResolver over the contract schema. Errors render inline under the field, worded as what to do.
  4. The amount is typed as a positive decimal. The tab decides the sign, and the client converts to a signed minor-units string by string manipulation, never through a JS number.
  5. The payload never contains an owner id.

Rules for this dialog

  1. Triggered by the 409 problem+json response. The reconciled date comes from lockedAt in that body. Never a toast, never a stack trace.
  2. Submits to the correction endpoint. On success the register shows the reversal and replacement dated today, and the original gets its Reversed badge (see the register screen).
  3. The form is prefilled from the original entry, so correcting a category is a one-field change.

Rules for these states

  1. Empty is an invitation to act. Its button is the same action, with the same name, as the header button.
  2. Loading keeps the table's row geometry so nothing jumps when data arrives. Shimmer stops under reduced motion.
  3. Error shows the detail from the problem+json body as written. The heading is ours; the explanation is the server's.
