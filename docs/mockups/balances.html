Rules for this screen

  1. Every figure on this screen comes from one balances response: per account, per group, and net worth. The browser displays numbers; it never adds them. Net worth is computed by the API as the raw signed sum over asset and liability accounts, which needs no sign logic at all.
  2. Group subtotals come from the same response. They are not the sum of the rows beneath them computed client-side.
  3. A liability shows what is owed as a positive amount with an owed label. The API has already applied the display sign; the client never flips one.
  4. Archived accounts stay hidden from this list, but their balances still count in the group subtotal and net worth. Hiding an account is presentation; its money is still real.
  5. The header balance is the selected account's figure from the same response. Switching accounts does not trigger a second balance request.
  6. An account with no transactions shows 0.00, never a blank or a missing row.
  7. No asOf in the URL means today. The client resolves today as the user's local date and always sends it to the API explicitly, so "today" is never the server's timezone.

Rules for this control

  1. Dates after today are disabled, and so is navigating to next month. A balance on a future date is a projection, which belongs to bills and projection, not to this story.
  2. Two quick picks only: Today, and End of last month, which is the date reconciliation works against. No other presets.
  3. Choosing a date writes asOf to the URL. The query key derives from the URL, so the back button returns to the previous date and a shared link reproduces the view.

Rules for this state

  1. A past date is never subtle. The banner, the as-of button, and every "as of" label switch to the past-date treatment together, so nobody mistakes last month's balance for today's.
  2. The balance date changes balances only. The register keeps its own range filter, and the banner says so in plain words.
  3. Back to today removes asOf from the URL rather than writing today's date into it. A link shared today and opened tomorrow then shows tomorrow's balance, which is what "today" meant.

Rules for these states

  1. A liability's slot is labelled Balance owed, and the amount is shown as returned. Stored as −80000, displayed as 800.00, because the API applied the display sign once in its mapper.
  2. An overdrawn asset shows a minus sign in normal ink. Red is reserved for errors; a negative balance is information, not a failure.
  3. Account names come from the account list and render immediately; balances are a separate request and shimmer in place. A slow balance query never delays the list.
  4. If balances fail, the list and the register still work. Figures show a dash, and one inline message offers a retry. The message carries the detail from the problem+json body, the same rule as the register's error state.
